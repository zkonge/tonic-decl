# tonic-decl

Declare [tonic](https://github.com/hyperium/tonic) gRPC client and server stubs with a
`macro_rules!` macro, without `build.rs`, `protoc` or `tonic-build`.

You write the [prost](https://github.com/tokio-rs/prost) message types (or generate them
once), then list the RPCs of the service in `define_grpc!`.

> Versions `0.0.x` have no stability guarantee, every release may break the API.

## Usage

```toml
[dependencies]
prost = "0.14"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
tokio-stream = "0.1"
tonic = "0.14"
tonic-decl = "0.0.1"
```

```rust,no_run
use tonic::{Request, Response, Result};

#[derive(Clone, PartialEq, prost::Message)]
pub struct HelloRequest {
    #[prost(string, tag = "1")]
    pub name: String,
}

#[derive(Clone, PartialEq, prost::Message)]
pub struct HelloReply {
    #[prost(string, tag = "1")]
    pub message: String,
}

tonic_decl::define_grpc! {
    /// The greeting service.
    Greeter, GreeterClient, GreeterServer, "helloworld.Greeter",

    /// Sends a greeting.
    fn say_hello("SayHello")(HelloRequest) -> (HelloReply);

    /// Sends a greeting for each name in the stream.
    fn say_hellos("SayHellos")(stream HelloRequest) -> (stream HelloReply) as SayHellosStream;
}

struct MyGreeter;

impl Greeter for MyGreeter {
    type SayHellosStream = tokio_stream::Iter<std::vec::IntoIter<Result<HelloReply>>>;

    async fn say_hello(&self, req: Request<HelloRequest>) -> Result<Response<HelloReply>> {
        let message = format!("Hello {}!", req.into_inner().name);
        Ok(Response::new(HelloReply { message }))
    }

    async fn say_hellos(
        &self,
        req: Request<tonic::Streaming<HelloRequest>>,
    ) -> Result<Response<Self::SayHellosStream>> {
        use tokio_stream::StreamExt;

        let mut names = req.into_inner();
        let mut replies = Vec::new();
        while let Some(req) = names.next().await {
            let message = format!("Hello {}!", req?.name);
            replies.push(Ok(HelloReply { message }));
        }

        Ok(Response::new(tokio_stream::iter(replies)))
    }
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let addr = "[::1]:50051".parse()?;
    let greeter = GreeterServer::new(MyGreeter).into_service();
    tokio::spawn(
        tonic::transport::Server::builder()
            .add_service(greeter)
            .serve(addr),
    );

    let channel = tonic::transport::Channel::from_static("http://[::1]:50051")
        .connect()
        .await?;
    let mut client = GreeterClient::new(channel);

    let reply = client
        .say_hello(HelloRequest { name: "tonic".into() })
        .await?;
    println!("{}", reply.into_inner().message);

    Ok(())
}
```

Each RPC is `fn method("MethodName")(Request) -> (Response);`. Prefix the request and/or
response with `stream` for streaming RPCs. A streaming response can name its stream type with
`as`, which becomes an associated type of the server trait. Without `as`, the trait method
returns `impl Stream`, so closures and other unnameable streams work without boxing.

Both the client and the server are generated by default. To make one side optional, put
attributes before its name, they are copied to every item of that side:

```rust,ignore
tonic_decl::define_grpc! {
    Greeter,
    #[cfg(feature = "client")] GreeterClient,
    #[cfg(feature = "server")] GreeterServer,
    "helloworld.Greeter",
    // ...
}
```

Unlike `tonic-build`, the server struct itself is not a `Service`: `into_service()` returns a
tower `Service` that works with `tonic::transport::Server`, `tonic::service::Routes` and
`tonic::service::interceptor::InterceptedService`. The stub
itself does no heap allocation per request; tonic's codec and router still do.

Not supported yet: compression (`send_compressed` / `accept_compressed`) and codecs other than
prost.
